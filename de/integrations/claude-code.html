Claude Code¶

MCP – Claude steuert das Fenster¶

Solange die App läuft, stellt sie MCP unter http://127.0.0.1:4340/mcp bereit (Streamable HTTP, nur lokal; anderer Port über MB_MCP_PORT). Einmal registrieren:

$ claude mcp add --scope user --transport http monsterbrain http://127.0.0.1:4340/mcp

Tool

Macht

get_view

Ordner, Modus, aktive Datei, offene Tabs, Ansicht, markierter Text; in einem JSON-/YAML-Baum der JSON Pointer des gewählten Knotens

open_file

eine Datei öffnen (Vorschau-Tab oder mit new_tab ein eigener Tab), optional mit Ansicht und einer Passage zum Hervorheben – bei JSON und YAML auch ein JSON Pointer (/colors/primary), der diesen Knoten im Baum auswählt

show_changes

zur Änderungsansicht wechseln, die geänderten Dateien zurückgeben

show_diff

den Diff einer Datei öffnen

open_folder

einen anderen Ordner öffnen

Erweiterungen fügen Tools hinzu (deciwa: deciwa_feedback, deciwa_show). Läuft die App nicht, meldet Claude Code den Server als nicht verbunden.

Agent-Aktionen – das Fenster gibt Arbeit an Claude¶

Aktionen erreichen eine Claude-Code-Session, die auf diesem Rechner läuft – im Code-Tab der Claude-Desktop-App oder in einem Terminal. Nichts einzurichten: Jede Session meldet sich selbst an und nimmt Nachrichten über einen lokalen Socket an (Agent-Aktionen gehen über d... (DEC_AGENT_SOCKET)).

Welche Session eine Aktion bekommt:

  1. Infrage kommen nur Sessions, deren Ordner den geöffneten Ordner enthält (oder in ihm liegt).

  2. Davon die Session, die am Konzept der Aktion arbeitet – sie hat im Ordner des Konzepts gelesen, geändert oder committet (bei einer Backlog-Aufgabe oder einer Datei außerhalb eines Konzepts: in dieser Datei). Die meiste Arbeit gewinnt (Die Session, die am Konzept... (DEC_SESSION_BY_CONCEPT)).

  3. Hat noch keine Session daran gearbeitet: Die einzige bekommt sie; bei mehreren fragt monsterbrain nach, welche, anhand des Session-Namens. Die Wahl merkt es sich bis zum Neustart der App.

  4. Gar keine Session: monsterbrain bietet Open in Claude desktop an – eine neue Desktop-Session im Ordner mit der Anfrage schon im Eingabefeld; du bestätigst den Ordner und schickst sie ab – oder Start in terminal: Ein Terminal öffnet sich im Ordner mit claude, und sobald sich diese Session angemeldet hat (bis zu zwei Minuten), schickt monsterbrain die Anfrage hinein (vorerst nur Linux).

    Bekanntes Problem (Claude Desktop 4.29.0, Linux): Die Desktop-App übernimmt den Ordner und speichert deine Bestätigung, startet die neue Session aber in einem leeren Scratch-Ordner. Wähle den Ordner in der neuen Session, bevor du abschickst.

Das empfangende Claude sieht die Aktion als Nachricht einer anderen Session, eingepackt in <monsterbrain action="…" path="…" concept="…">, mit dem Hinweis, dass du sie in monsterbrain geklickt hast. Eine Session, die Berechtigungsabfragen überspringt, hält so eine Nachricht unter Umständen zurück, bis du sie erlaubst (Einstellung crossSessionInbound).

Bemerkung

monsterbrain findet Sessions und schickt ihnen Nachrichten über eine Schnittstelle von Claude Code, die nicht dokumentiert ist: die Session-Liste in ~/.claude/sessions/ und das Nachrichtenformat ihres Sockets. Ein Update von Claude Code kann sie ändern; dann fallen Aktionen auf den Dialog zurück (Das Session-Verzeichnis und... (Q_SOCKET_UNDOCUMENTED)). Details: MCP und Agent-Aktionen.

Ctrl Shift A schickt „erkläre diese Datei“ (mit dem markierten Text).

Der Claude-Knopf im Kopf der Datei ist ein geteilter Knopf. Sein linker Teil ist der Haupteintrag einer Erweiterung – deciwa: Inform Claude; ohne einen heißt der ganze Knopf Claude ▾. ▾ öffnet das Menü:

  • Implement concept – für eine Datei im Ordner eines offenen Konzepts mit offenen Aufgaben (nicht für Dateien, die das Konzept nur unter results: aufführt): Claude erledigt jeden nicht abgehakten Punkt der Liste ## Tasks des Konzepts, der Reihe nach, hakt jeden ab und committet nach jedem Schritt. Ideen, Notizen und offene Fragen an anderer Stelle im Konzept sind keine Aufgaben. Eine Aufgabe, die dich braucht – eine Antwort, ein Review, ein Neustart zum Testen – beendet den Lauf. Das Menü zeigt, wie viele Aufgaben offen sind, ihre Liste beim Darüberfahren. Mit deciwa liest Claude zuerst das Review von concept.md und überspringt die Aufgaben, die du abgelehnt hast.

  • Close concept – der Klick ist deine Freigabe: Claude setzt status: approved und schließt das Konzept mit dem Skill close-concept. monsterbrain fragt vorher.

  • Discard concept – monsterbrain setzt selbst status: discarded (nach Rückfrage); nichts wird übernommen, der Ordner bleibt. Ein verworfenes Konzept gilt als geschlossen.

  • Implement task – für eine offene Backlog-Aufgabe (05_backlog/, status: open): Claude prüft zuerst, ob die Aufgabe klar ist, und fragt dich, bevor es etwas ändert; eine Aufgabe, die für einen Durchgang zu groß ist, schlägt es als Konzept vor. Es schließt den Eintrag nicht. Mit deciwa liest es zuerst das Review des Eintrags.

  • Close task (oder Close question) – Claude setzt den Eintrag auf done und verschiebt ihn nach 90_archive/backlog/. monsterbrain fragt vorher.

  • Discard task (oder Discard question) – nicht mehr gewollt: Claude setzt den Eintrag auf discarded und verschiebt ihn nach 90_archive/backlog/, wie ein verworfenes Konzept nie erledigt. monsterbrain fragt vorher.

  • Message to Claude … – ein freier Text, geschickt mit der offenen Datei, ihrem Konzept und der Stelle, die beim Öffnen des Menüs markiert war, als Kontext. Ctrl Enter schickt ab.

Aktionen starten immer nur durch einen Klick oder eine Taste.
