Product¶

Decision: A desktop app, not a server started by hand DEC_DESKTOP_APP
status: approved
decided: 2026-10-20
reason: The app starts, watches and stops whatever it needs internally; no console.
alternatives: a local server opened in the browser.
Decision: Layout: tree left, content in the middle, metadata right DEC_LAYOUT
status: approved
decided: 2026-10-20
reason: As in the viewer mockup, with the danwos tool branding.
Decision: The folder structure stays unchanged – monsterbrain reads it and imposes none DEC_STRUCTURE_UNCHANGED
status: approved
decided: 2026-10-20
reason: The folder belongs to its user and their agents; the app adapts to it.
Decision: The change view works on folders; Git supplies changes where a folder is a repository DEC_CHANGES_ON_FOLDERS
status: approved
decided: 2026-10-20
reason: The knowledge folder and the code repositories next to it are watched the same way.
alternatives: the knowledge folder only.
Decision: monsterbrain keeps no state about user interactions DEC_NO_INTERACTION_STATE
status: approved
decided: 2026-10-20
reason: Seen, read and done are review state – a deciwa feature that comes with the deciwa extension.
alternatives: an own "seen" state in the app.
Decision: Claude controls the app through a local MCP server; a chat inside the app comes later DEC_CLAUDE_MCP
status: approved
decided: 2026-10-20
reason: The most for the least effort, one chat place, works with every MCP-capable agent, no API key in the app.
alternatives: a chat panel inside the app (embedded terminal or Agent SDK).
Decision: A click on a picture opens it as its own file DEC_IMAGE_CLICK
status: approved
decided: 2026-10-29
reason: A picture in a concept is often too small to read; on its own it can be zoomed. In deciwa's review mode a plain click stays with the review, Ctrl click opens – as for links. Pictures in HTML pages stay out.
alternatives: a lightbox over the file; zoom inside the rendered Markdown.
Decision: Back and forward per tab, like a browser, only through link and picture clicks DEC_TAB_HISTORY
status: approved
decided: 2026-10-29
reason: After following a picture or link far away in the tree, one click on the mouse's back button returns to the same view and scroll position. Files opened from the tree or with j / k replace the preview tab and stay out – the tree is a quick look.
alternatives: one history for the whole window; the tree's files in the history too.
Decision: The image view zooms with + and - only, no other single keys DEC_IMAGE_ZOOM_KEYS
status: approved
decided: 2026-10-29
reason: deciwa uses digits for stars and letters for its review; Fit and 1:1 are buttons, zoom also works with Ctrl and the wheel or a pinch.
alternatives: 0 for fit and 1 for 1:1, a double click to toggle.

Agent actions¶

Decision: Agent actions go to the running Claude Code session DEC_AGENT_RUNNING_SESSION
status: approved
decided: 2026-10-22
reason: You and Claude work on the result together, with the chat context of the session.
alternatives: a new background session per action, MCP prompts as slash commands, copying the prompt.
Decision: Agent actions are only ever started by hand DEC_AGENT_BY_HAND
status: approved
decided: 2026-10-22
reason: monsterbrain offers (button, key), the user decides; no event – e.g. a finished review – starts an agent.
alternatives: start the agent automatically when a review is finished.
Decision: "Start Claude here" is enough to make agent actions simple DEC_START_CLAUDE_HERE
status: approved
decided: 2026-10-22
reason: One click when no session listens; the start script and the channel flag stay hidden. Since 2026-10-30 the dialog offers a new desktop session first and the terminal second (DEC_AGENT_SOCKET).
alternatives: a setup button with a short command, an embedded terminal in the app, a Claude Code plugin.
Decision: Agent actions go through the session's messaging socket DEC_AGENT_SOCKET
status: approved
decided: 2026-10-30
reason: Works in the Claude desktop app, where channels are not available, and needs no start script or flag. The interface is undocumented; that risk is accepted, the dialog is the fallback.
alternatives: channels only (terminal); a deep link per action (prefilled only, a new session each time); an MCP tool Claude would have to poll.
Decision: The session that works on the concept gets the action DEC_SESSION_BY_CONCEPT
status: approved
decided: 2026-10-30
reason: Several sessions often work in the same folder, one per concept; the one that did the concept's work has its context. A busy session may get it; with none, Daniel picks.
alternatives: the idle session first (actions landed in the wrong session); always ask; a session claims a concept through an MCP tool.
Decision: Generic parts in monsterbrain, the review action in deciwa, no extra review state DEC_AGENT_GENERIC
status: approved
decided: 2026-10-22
reason: monsterbrain knows sessions and concepts, deciwa knows the review; every review entry has a created time, so Claude finds what is new itself and deciwa keeps no per-user files.
alternatives: the action built into monsterbrain; deciwa storing when the agent was last informed.
Decision: One Claude button per file: a split button with a menu DEC_CLAUDE_BUTTON
status: approved
decided: 2026-10-23
reason: The frequent action (an extension's main entry, deciwa: Inform Claude) stays one click; everything else is one menu away.
alternatives: one button that always opens the menu; a button per action.
Decision: Concept actions and the message live in monsterbrain; extensions add to their prompts DEC_CLAUDE_ACTIONS_IN_APP
status: approved
decided: 2026-10-23
reason: Concepts and free messages are not review; they work without deciwa. deciwa adds what it knows – the review of concept.md – through ctx.agentPrompt.
alternatives: all actions in deciwa's button.
Decision: "Implement concept" does every open task of ## Tasks, and nothing else DEC_IMPLEMENT_ALL_TASKS
status: approved
decided: 2026-10-23
reason: The task list is the plan; ideas and notes elsewhere in the concept are not work yet. A task that needs the user ends the run; tasks rejected in deciwa are skipped.
alternatives: only the next task per click.
Decision: "Close concept" is the approval DEC_CLOSE_IS_APPROVAL
status: approved
decided: 2026-10-23
reason: One click instead of editing the status first; monsterbrain asks before it goes out.
alternatives: the entry only enabled when the status is approved.
Decision: "Discard concept" only sets status: discarded DEC_DISCARD_STATUS_ONLY
status: approved
decided: 2026-10-23
reason: Nothing is lost and nothing needs Claude; a discarded concept counts as closed.
alternatives: archive the folder with a skill; delete it.
Decision: "Message to Claude" only with an open file DEC_MESSAGE_NEEDS_FILE
status: approved
decided: 2026-10-23
reason: The open file is the context of the message.
alternatives: a message about the whole folder.
Decision: Concept actions only for files inside the concept's folder DEC_CONCEPT_ACTIONS_INSIDE
status: approved
decided: 2026-10-23
reason: A fact or an output a concept lists under results: is not the concept; implementing or closing it from there surprises.
alternatives: concept actions for every file a concept lists.
Decision: Backlog tasks get their own Claude actions: implement, close and discard DEC_TASK_ACTIONS
status: approved
decided: 2026-10-23
reason: A small task can be done without a concept. Claude asks first when the task is unclear and does not close it itself; closing or discarding is a click of the user.
alternatives: every backlog task goes through a concept.
Decision: One word for "not wanted any more": discarded, for concepts and backlog items DEC_DISCARDED_EVERYWHERE
status: approved
decided: 2026-10-23
reason: Concepts and backlog items are abandoned the same way; one status and one menu word (Discard) for both. A discarded concept stays in its folder, a discarded backlog item moves to the archive like a done one.
alternatives: dropped for backlog items, discarded for concepts.

Technical¶

Decision: Electron with TypeScript DEC_ELECTRON
status: approved
decided: 2026-10-20
reason: The same Chromium on every system, so HTML outputs look like in Chrome; Linux is stable; one language for UI and core.
alternatives: Tauri – much smaller download and RAM, but a different web engine per OS (WebKitGTK on Linux) and Rust as a second language.
Decision: Two repositories: the app, and later the shareable brain setup DEC_TWO_REPOS
status: approved
decided: 2026-10-20
reason: The setup (folder skeleton, AGENTS.md, templates, skills, example section) is shared on its own; the app is distributed later.
alternatives: one repository.
